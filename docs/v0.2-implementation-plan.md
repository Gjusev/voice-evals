# voice-evals v0.2 implementation plan

Planning baseline: local v0.1.1 source, Python 3.10+, and the existing clef-evals/laya-evals Kaggle publishing conventions. Includes the requested support for current open models. This document specifies contracts and configuration; it does not implement the feature.

Ship a deterministic scripted caller, a full-duplex WebSocket probe, reusable recordings, and an offline Kaggle reproduction. Keep `jiwer` as the only base runtime dependency. Add network clients through an optional extra. Use the existing evaluator for canonical scores; keep richer session diagnostics alongside its unchanged result fields.

Three boundaries govern the design:

- Internet-disabled Kaggle cannot download packages from PyPI during execution. Kernel A must install the exact published PyPI wheels from a preattached, checksummed Kaggle dataset.
- A WebSocket URL alone does not specify an audio protocol. Supply a documented default protocol and a small declarative map; unsupported protocols require adapters.
- Client-observed events cannot reveal hidden STT, LLM, or TTS stages. Missing measurements remain unavailable, and approximations carry their measurement basis.

Changes to existing files:

- Leave the four existing `Scenario` fields unchanged. Define `ScenarioScript` as an extension of `Scenario`, with extra script fields. `to_scenario()` explicitly projects the replay fields.
- Do not add mandatory fields to `CallRecord`, `StageTimings`, or `Interruption`. Add a `CallRecord.to_dict()` helper using the already accepted `stage_timings_ms` and interruption keys. Keep `agent_stopped_ms` as a duration after interruption, not a session timestamp.
- Existing `CallRecord.from_dict()` already selects known scenario fields. A scenario containing v2 extensions can therefore be embedded in a replay row without breaking old readers. A legacy scenario can load as a script with no steps for replay use; probing it produces an actionable validation error.
- Leave `evaluate()`'s WER, exact outcome matching, substring fact matching, and per-call aggregation unchanged. Do not introduce semantic judging under existing metric names.
- Preserve all existing result keys and their types. Add one `probe` object and `gate_passed` in probe output. Rich turn metrics live in that additive object or the manifest.
- Preserve existing `run` behavior and exit codes. New probe gates fail closed on unavailable requested measurements; do not silently change legacy replay gate behavior in this release.
- Keep all optional network imports inside their adapter modules or factories. Importing replay APIs, the runner, interfaces, fixtures, and mocks must work with the base installation.
- Explicitly package JSON resources in the wheel. Tests and the larger benchmark also ship in the reproduction bundle; a PyPI wheel does not implicitly contain repository tests.

## 2. Public contracts

The following are signature specifications, not implementation bodies. Use standard-library dataclasses, enums, and `typing.Protocol`. Do not require Pydantic or a plugin framework.

```python
class ScenarioScript(Scenario):
    schema_version: int
    seed: int
    facts: dict[str, str]
    steps: tuple[ScriptStep, ...]
    outcome_rule: OutcomeRule

    @classmethod
    def from_dict(cls, value: Mapping[str, object]) -> ScenarioScript: ...
    @classmethod
    def load(cls, path: str | Path) -> ScenarioScript: ...
    def to_scenario(self) -> Scenario: ...
    def validate_for_probe(self, capabilities: TransportCapabilities) -> None: ...
    def select_utterance(
        self, step_id: str, observation: AgentObservation
    ) -> SelectedUtterance | None: ...

class CallerVoice(Protocol):
    async def synthesize(
        self,
        text: str,
        *,
        audio_format: AudioFormat,
        seed: int | None = None,
    ) -> SynthesizedAudio: ...
    async def aclose(self) -> None: ...

class AgentTransport(Protocol):
    async def open(self, config: TransportConfig) -> TransportCapabilities: ...
    def events(self) -> AsyncIterator[AgentEvent]: ...
    async def send_audio(self, frame: CallerAudioFrame) -> SendReceipt: ...
    async def end_utterance(self, utterance_id: str) -> None: ...
    async def cancel_response(self, response_id: str) -> ControlReceipt: ...
    async def aclose(self) -> None: ...

class SessionRunner:
    def __init__(
        self,
        *,
        caller: CallerVoice,
        transport: AgentTransport,
        config: ProbeConfig,
        clock: Clock | None = None,
    ) -> None: ...
    async def run(
        self, script: ScenarioScript, *, output_dir: Path
    ) -> SessionRecord: ...

def to_call_record(session: SessionRecord) -> CallRecord | None: ...
def score_session(session: SessionRecord) -> ProbeReport: ...
```

Contract details:

| Type | Required information and behavior |
| --- | --- |
| `AudioFormat` | Encoding identifier, sample rate, channels, sample width, byte order. v0.2 wire support is PCM signed 16-bit little-endian, mono. Input and output formats are separate. |
| `SynthesizedAudio` | PCM bytes, exact format, sample count, text, synthesis provenance, content hash. Duration derives from samples, never HTTP chunk count. |
| `CallerAudioFrame` | Utterance ID, sequence number, payload, sample offset/count, format, planned send time. |
| `SendReceipt` | Local monotonic timestamps immediately before and after the actual socket send, accepted byte count; explicitly not a remote playback acknowledgment. |
| `AgentEvent` | Event kind, local receipt time, optional provider time and clock domain, event/utterance/response/segment IDs, direction, typed payload. Audio events include format, samples and payload reference. |
| `AgentObservation` | Current response's finalized agent text and explicit intent events, response ID, response-completion evidence. No concatenated whole-call matching for branches. |
| `TransportCapabilities` | Formats, duplex support, audio pacing semantics, caller/agent transcript availability, response IDs, speech/end events, stage events, explicit input commit, cancellation, playback acknowledgments. Distinguish declared from observed capabilities. |
| `TransportConfig` | Endpoint/auth references, protocol map, frame duration, handshake/heartbeat/size limits. Secrets excluded from representation and serialization. |
| `ProbeConfig` | Timeouts, output limits, alternative seed, barge-in detection/gate thresholds, expected capabilities, caller settings. |

Exactly one task consumes `events()`; one serialized writer sends audio/control messages. The transport stamps receipt before normalization or disk I/O and stamps send at the socket boundary. The runner dispatches normalized events to script, timing, and recording logic. Adapters do not receive expected outcomes or hidden caller facts.

`end_utterance()` maps to commit/create-response messages only when the protocol requires them; it is a no-op for native server VAD. Unsupported cancellation raises a typed capability error. The normal barge-in experiment does not call cancellation.

Caller synthesis returns complete clips deliberately: the scenario has a bounded set of utterances, and preparing them before the call avoids contaminating agent measurements with caller TTS latency. A future streaming caller can be introduced separately without changing transport or session event formats.

## 3. Scenario v2: schema and worked example

Use JSON Schema Draft 2020-12 as the published contract. Validate runtime input with a small typed parser; use `jsonschema` only as a development dependency to check examples and parser agreement. Reject unknown fields rather than silently ignoring misspelled cues.

This is the complete structural schema for the proposed small v2 language:

```json

Additional semantic validation: IDs must be unique; references must identify prior steps; branch and cue response references must agree; outcome references must exist; first step must speak immediately; placeholders must refer to declared facts; each substituted fact must appear in `reveals`; reject unused/mismatched reveal declarations. A skipped referenced step causes an explicit unreachable-dependency result, never an indefinite wait. Cap text length and total synthesis size in config.

```

Expected fixture dialogue: the agent asks for the caller's name after turn 1; offers 10:00 in a response long enough to interrupt after turn 2; acknowledges the correction after turn 3; confirms all booking details after turn 4. This is a fixture expectation, not an instruction sent to the agent.

Conditional behavior is deterministic and bounded: evaluate the predicate against the completed response to `request`, using case-insensitive literal substring matching. Reveal the name only if that predicate matches. Otherwise stop with `scenario_unmet`; this script intentionally tests whether the agent asks. Other scripts can use `skip`. v0.2 does not generate open-ended answers or let an LLM choose branches.

Select one alternative per step using a stable hash of scenario seed and step ID, then record the chosen index and rendered text. Selection must not depend on branch execution order. The chosen text, not every alternative, becomes caller ground truth. `intent` is caller metadata; it is never injected into the agent's audio channel.

The text outcome rule is an explicitly limited proxy for what the agent reported, not evidence that a calendar write succeeded. For production scenarios prefer `source: transport` and map the agent's structured outcome event. Never copy `expected_outcome` into the actual outcome merely because the script completed.

## 4. Transport protocol map

Provide `default-v1.json` with a documented reference protocol. Support JSON/base64 media or binary PCM media with JSON control events. Both must allow a concurrent receive stream.

The map contains:

- Independent input/output audio declarations: encoding, rate, channels, sample width, frame duration, streaming versus burst output.
- Handshake templates and a readiness event, with a bounded ready timeout. A no-handshake protocol becomes ready on successful socket open.
- Outbound audio envelope template, optional utterance-end templates, optional cancel template, optional silence/keepalive policy.
- Inbound event discriminator and JSON-pointer field selectors for audio, role, text, IDs, final/delta flags, error codes, and provider timestamps.
- Input/output transcript roles, delta-versus-snapshot semantics, and response correlation rules.
- Capability declarations and authentication through environment references only.

Example mapping contract: outbound `type=input_audio`, `utterance_id`, `seq`, and base64 `audio`; inbound `type=output_audio` maps to agent audio, `type=input_transcript_final` to caller ASR, `type=output_text_delta/final` to agent text, and `type=response_done` to completion. Structured `outcome` and stage-start events are optional.

Use JSON Pointer traversal and a fixed allowlist of substitutions such as audio payload, sequence, utterance ID, and environment-backed auth fields. Do not evaluate Python, Jinja, arbitrary JSONPath expressions, or scripts from a map. Reject ambiguous media/direction mappings. Do not expose the caller fact bank as a substitution source.

Unknown nonessential events may be counted and ignored. Malformed mapped events, conflicting format changes, invalid base64, frame-size overflow, or unsupported binary headers are typed protocol failures. Specify WebSocket maximum message size and disable compression for PCM by default.

Responses must be correlated using provider IDs when available. Serial response association can support ordinary request/reply without IDs; overlapping old/new responses cannot be disambiguated reliably and must disable precise barge-in timing. Transcript updates replace prior snapshots or append deltas according to the map; never concatenate every interim snapshot.

Future Twilio/Telnyx adapters can normalize inbound accepted streams, stream identifiers, codec conversion, and mark/clear events behind this interface. `open()` means acquiring a usable session, not necessarily dialing an outbound socket. A future OpenAI Realtime adapter can own session initialization, append/commit/create, cancellation, and truncation. Those behaviors belong in adapters, not in the runner or an ever-growing map language.

“Works with any agent” means any agent whose exposed protocol fits the supported map and capabilities. A URL alone, a telephony media webhook, an ASR-only socket, and an arbitrary proprietary binary protocol are not interchangeable.

## 5. Session state and concurrency

Use a session lifecycle plus independent caller/agent activity. One linear `SPEAKING` state cannot represent barge-in.

```text
NEW -> VALIDATING -> PREPARING_AUDIO -> CONNECTING -> READY -> ACTIVE
ACTIVE -> DRAINING -> FINALIZING -> COMPLETED
any active state -> FAILED or CANCELLED -> FINALIZING -> PARTIAL/FAILED

caller: IDLE -> WAITING_FOR_CUE -> SENDING -> IDLE
agent:  IDLE -> RESPONDING -> END_PENDING -> IDLE
                              ^
barge-in runs caller SENDING while agent RESPONDING
```

State transition rules:

| Transition | Work and captured observations |
| --- | --- |
| Validate | Parse script/map, resolve config, check capability requirements and output bounds. Start manifest and UTC creation timestamp; reserve session ID. |
| Prepare | Render selected alternatives and synthesize reachable conditional clips before connecting. Record each TTS start/end separately from agent latency. Cache only within the run by text/voice/model/settings/format hash. |
| Connect/ready | Start shared monotonic session clock; capture connection start, socket-open, ready and negotiated format events. The same clock instance timestamps runner and adapters. |
| Arm step | Record cue activation, referenced response, branch result, alternative index, and intended send deadline. |
| Start sending | Record first successful audio send start/completion, utterance ID, sample zero, and interruption start when applicable. |
| Send each frame | Record planned deadline, actual send start/completion, bytes, sample offset, sequence, and scheduling lateness. |
| Finish caller | Record final frame send and its sample duration; input commit time separately. Caller audio end is the paced end of its final sample, not the instant the final frame was enqueued. |
| Receive | Timestamp every application audio message and control/transcript event before processing; retain its media offset and optional provider time. |
| Response finish | Prefer explicit end plus media-drain evidence. Otherwise infer using configurable quiet time and known queued media duration; label inference. |
| Drain | After the final script step, await its response completion and late final transcripts, bounded by response and drain deadlines. |
| Finalize | Close clients, flush journal and audio, evaluate eligibility, write record/result and atomically replace manifest. Record terminal status and reason. |

The receiving task remains active during waits, caller speech, and interruption measurement. Event dispatch must not block on synchronous file writes: buffer bounded batches or use a writer worker. Timestamping occurs before queue insertion. If recording/backpressure exceeds configured bounds, fail visibly rather than dropping audio silently.

Use `asyncio.create_task`, `wait_for`, and explicit cancellation with `gather(..., return_exceptions=True)` for Python 3.10 compatibility. Do not depend on 3.11-only `TaskGroup` or `asyncio.timeout`. Close resources in `finally`; preserve records on Ctrl-C. A fake clock drives unit tests without sleeping in real time.

Defaults: connect/ready 10 seconds each; first-response 15 seconds; response completion 30 seconds; whole call 120 seconds; final drain 2 seconds; frame duration 20 ms. Scenario cue timeouts can narrow the relevant waits. All values are configurable and recorded.

## 6. Timestamps, stage timings, and barge-in

Use `time.perf_counter_ns()` for all local duration arithmetic, storing session-relative integer nanoseconds. UTC is for run identity only. Provider timestamps remain in their own clock domain; never subtract them from local timestamps without an explicit synchronization method.

The frame journal records complete application media messages. A WebSocket library generally exposes complete messages, not network packet or TCP-fragment arrival times. Therefore “first agent audio byte” means the first nonempty audio payload observed by the application, with this measurement boundary documented.

For caller utterance `u` and correlated agent response `r`:

| Measurement | Definition and availability |
| --- | --- |
| Caller end `C_end` | Final frame send completion plus that frame's sample duration, under paced transmission; retain scheduled end and lateness as well. It is a client send-side estimate, not proof of remote playback. |
| E2E | First audio payload of the new response `r` received after `C_end`, minus `C_end`. Require response correlation. For response onset before caller end, retain signed overlap diagnostically and exclude from ordinary nonnegative E2E aggregates. |
| STT approximation | Receipt of final caller transcript covering `u`, minus `C_end`. Include endpointing and network delivery; label `client_final_asr`. If finalized early, preserve the signed diagnostic and do not clamp into a zero latency. |
| LLM TTFT | First actual LLM-token event minus LLM-start event, in the same clock domain. If only ASR-final and agent text are exposed, report `asr_final_to_agent_text_ms` separately as a proxy. An audio transcript delta is not necessarily an LLM token. |
| TTS TTFA | First audio minus explicit TTS-start, correlated to the first synthesis segment and measured in one domain. With only text/audio observations, expose `first_text_to_audio_ms` separately as a proxy. |

Only populate legacy `llm_ttft_ms`/`tts_ttfa_ms` when their event semantics support those names. Keep unsupported fields `None`. STT is explicitly an approximation in the manifest. For native speech-to-speech agents, separate STT/LLM/TTS stages may not exist; still measure observable E2E and interruption behavior.

Store per-utterance timings, response IDs, event references, availability reasons, measurement basis, and clock domain. Per-turn results group the caller utterance with its response; additional agent audio/text segments remain separate utterance records. Do not pretend stage intervals sum to E2E: stages may overlap or include different network boundaries.

For the legacy call-level `StageTimings`, use the arithmetic mean of valid ordinary-turn observations for each field. Record support counts and `aggregation=mean_of_observed_nonoverlap_turns`. Existing E2E p50/p95/p99 remain percentiles across CallRecords, therefore across call-level means for these new sessions. Add separate `probe.turn_latency` percentiles and counts; never replace the existing fields with turn-weighted metrics.

A live session and its exported replay record must produce identical legacy scores. Comparing different datasets still requires the same call aggregation, timing basis, coverage policy, caller voice, and execution location. A one-call diagnostic does not establish a population p95.

Barge-in procedure:

1. Arm the marked step against the response to its named prior caller step.
2. Start its deadline at the first agent audio payload for that response; at `after_ms`, verify that response is still observably active. Require genuinely incremental output or trustworthy media/playback progress. Already-burst-completed output is not proof of ongoing speech.
3. Send caller audio without pausing receive. Let `B` be the first successful caller media send-start timestamp. Record send-completion uncertainty too.
4. Continue receiving old-response audio. Let `L` be the receipt time of its last post-`B` audio frame, confirmed by an explicit end or a configured quiet window.
5. Set `Interruption.at_ms = B - session_origin`; set `agent_stopped_ms = L - B`. If the response was demonstrably active at `B` and ended without any later frame, report an observed zero with an uncertainty note. If activity was not established, report unavailable, not zero.
6. Record the quiet-window confirmation time separately; do not add the quiet window to the stop latency. Late old-response frames reopen the observation and move `L` until the bounded observation window closes.
7. Keep old-response frames separate from the new response to the interruption. If correlation is ambiguous, report unavailable. A socket close, recorder failure, or explicit client cancel is not a successful natural stop.

Use separate knobs: `agent_quiet_ms=300` for inferred cessation, `max_barge_in_stop_ms=500` for the success threshold, and `barge_observation_timeout_ms=5000` for bounded observation. Timeout without a confirmed end is right-censored: retain a lower bound and `not_stopped`; do not fabricate a stop duration.

The existing median includes only measured stops. Add attempted, observed, missed, unsupported, timed-out, and censored interruption counts so it cannot hide failed attempts. A requested interruption gate fails on missing/censored required attempts as well as excessive measured latency.

The metric measures cessation of received audio, not physical speaker silence. If a future adapter exposes playback acknowledgments, record playback stop separately. Do not automatically send a cancellation/clear event during natural barge-in testing; explicitly assisted cancellation would be a different experiment.

## 7. Audio and dependencies

Request native PCM from ElevenLabs: `POST /v1/text-to-speech/{voice_id}?output_format=pcm_16000` or `pcm_24000`, matching the agent's declared input rate. The request input is text; MP3 is the default response format that this adapter overrides. ElevenLabs documents the `output_format` query and higher-tier restrictions for 44.1 kHz PCM. [ElevenLabs API](https://elevenlabs.io/docs/api-reference/text-to-speech/convert)

Initial supported input/output rates: 16 kHz and 24 kHz, independently selectable, mono PCM S16LE. Other codecs/rates fail preflight unless an explicit adapter supports them. No silent resampling. Output WAV files retain their stream's native supported rate.

At 20 ms, send 640 bytes at 16 kHz or 960 bytes at 24 kHz. Frame on sample boundaries; the final short frame is valid unless a protocol requires padding. Record padding separately and exclude it from spoken ground truth. Anchor pacing to cumulative sample duration so scheduling drift does not accumulate. Never blast a complete utterance into a real-time transport as fast as possible.

Validate ElevenLabs response status, format metadata where supplied, sample alignment, nonempty bytes, and configured size limits. Reject recognizable MP3/WAV/error-body responses when raw PCM was requested. Headerless PCM cannot prove its own sample rate; the request, provider contract, and conformance fixture are the source of truth.

Store caller sent audio and received agent audio separately, with per-utterance/response WAV files and frame indexes. Concatenated WAV audio alone is insufficient for timing because it loses inter-frame gaps; the journal is authoritative. A timeline WAV can be derived with silence insertion, but is optional.

Dependency decision:

| Installation | Dependencies added | Reason |
| --- | --- | --- |
| `voice-evals` | None beyond existing `jiwer` | Replay, interfaces, runner, mocks, fixture voice, PCM/WAV handling use the standard library. |
| `voice-evals[probe]` | `httpx>=0.27,<0.29`, `websockets>=15,<16` as initial tested ranges | HTTPX supplies the injected async HTTP client for ElevenLabs and open-model callers; websockets supplies actual full-duplex WS/WSS. Lock exact versions for reproduction and revisit ranges after conformance testing. |
| Development | `jsonschema` in addition to existing pytest/ruff | Validate the published schemas/examples and parser parity. No async pytest plugin is necessary when tests use `asyncio.run`. |
| Kaggle publisher | Kaggle CLI, outside package dependencies | Host-side push/status/output only. |

HTTPX supports reusable async clients; websockets has the separate async WebSocket client needed here. Its 15.0.1 package supports Python 3.9+, so the proposed range includes Python 3.10. [HTTPX async API](https://www.python-httpx.org/async/), [websockets package metadata](https://raw.githubusercontent.com/python-websockets/websockets/15.0.1/pyproject.toml)

Do not add FFmpeg, pydub, torchaudio, soundfile, NumPy, a provider SDK, or a resampler to the harness. WAV wrapping uses `wave`; PCM framing uses bytes and sample arithmetic. Do not use `audioop`, which would undermine modern Python compatibility. If a caller service can produce only MP3, it is unsupported in v0.2 until it serves PCM; do not install a decoder implicitly.

## 9. Recording, scoring, and failure policy

Each output directory contains:

```text
manifest.json
events.jsonl
calls.jsonl
result.json
audio/caller/<utterance-id>.wav
audio/agent/<response-id>.wav
```

The manifest contains its schema version, session ID/status/reason, UTC start, package/Python/platform versions, environment label (`local`, `kaggle`, `mock`), script and protocol hashes, sanitized effective config, chosen alternatives/branches, synthesis provenance, negotiated capabilities, ordered transcript segments, frame indexes, per-turn metrics and their provenance, interruptions, errors, scoring eligibility, file paths/hashes, and cleanup status.

`events.jsonl` is append-only and flushed periodically. Write an initial manifest before networking; finalize using a temporary file plus atomic replacement. Hard process termination may leave an explicitly incomplete manifest and a truncated final journal line; document recovery rather than promise crash-proof finalization. Audio files contain only bytes actually sent/received, and partial utterances are marked.

Secrets are resolved at execution time and never serialized. Public config records environment variable names and a user-facing agent label, not raw URLs, authorization headers, signed query strings, key values, or exception request objects. Keep transcript content but omit unmapped raw control payloads; store only allowlisted provider fields. Disable client debug logs and redact known secrets before artifact writes. Secret-safe error types expose a category, safe status code, and remediation without dumping response bodies. Paths are generated locally from safe IDs.

Conversion rules:

| Existing field | Live source |
| --- | --- |
| `scenario` | Replay projection of the same v2 scenario. |
| `ground_truth_transcript` | Ordered selected text for fully sent utterances; skipped steps excluded. Mark this as script-derived ground truth, since a TTS model can mispronounce or hallucinate. Reviewed fixture audio has stronger provenance. |
| `asr_transcript` | Final caller-side transcripts from the actual agent pipeline, ordered by utterance/sample association. Never use agent speech transcripts or copy ground truth as ASR. |
| `agent_transcript` | Final agent output transcripts, de-duplicated and ordered. Text produced for unplayed generated audio remains flagged in the manifest; do not claim it was physically heard. |
| `outcome` | Structured reported outcome, or the explicitly configured deterministic final-text rule. No evidence of success yields an empty outcome when the observation is complete. |
| `stage_timings` | Documented per-call means from valid observed ordinary turns. |
| `interruptions` | Session-relative starts and observed stop durations, preserving unavailable values as `None`. |

Canonical scoring eligibility is strict because v0.1 requires numeric WER and fact scores without an unavailable state. A call must have reliable ground truth for its sent audio, complete caller ASR coverage, complete agent transcript coverage (or confirmed silence), and a completed observation window for its outcome. Optional stage events may be absent.

For eligible sessions, write a canonical CallRecord and call the existing `evaluate([record])`. Task failure is still a valid scored call. Exported `calls.jsonl` must replay to the same legacy result projection. Keep `failures` as returned by the existing evaluator; report execution failures additively under `probe.execution_failures` rather than silently redefining that existing field.

For ineligible sessions, retain all artifacts and compute only available diagnostics separately. Do not feed invented ASR or incomplete evidence into `evaluate()`. `calls.jsonl` is empty and marked non-replayable in the manifest. `result.json` still contains every v0.1 result field: `samples=0`, `failures=0`, numeric rate fields set to 0.0 as empty-result placeholders, latency/stop values `null`, `stage_means_ms={}`, and `details=[]`. Add `probe.scoring_status="not_scored"`, explicit exclusion reasons and coverage, and `gate_passed=false`. The summary prints “NOT SCORED,” never those placeholder rates. Do not call `evaluate([])`, which remains an error. The zero-sample convention preserves field types; consumers must not interpret zero-sample aggregates as measurements.

Every probe report adds attempts, scored calls, excluded calls, execution failures, behavioral failures, metric support counts, source/basis, run mode, and gate reasons. Gating requires a nonzero scored sample plus evidence for each requested metric. A missing metric cannot pass a requested threshold. Do not merge partial diagnostics into headline aggregate statistics.

| Failure | Handling | Scoring and CLI outcome |
| --- | --- | --- |
| Agent never responds while socket stays healthy | Bounded response timeout; retain sent audio and any ASR; distinguish no audio from no transcript events. | If caller/agent observations are complete, score task failure with absent E2E; exit 1. If evidence is missing, diagnostic-only, exit 1 with explicit reason. |
| Agent ignores a required question/correction or misses an interrupt window | Terminal `scenario_unmet` or `barge_in_missed`; retain completed dialogue. | Score task failure when eligible; required probe behavior fails even if some outcome text looks successful. Exit 1. |
| Socket drops mid-call | Mark partial; cancel send task, drain local buffers, finalize; no reconnect-and-resume in v0.2. | Exclude from canonical score; exit 2. Completed evidence remains available diagnostically. |
| TTS auth/quota failure | Catch before connecting because utterances are prepared first. Authentication and exhausted quota are not retried. | No scored call; manifest/error result; exit 2. |
| Transient TTS throttling/5xx | Bounded retries before the call, honor Retry-After, record attempts and potential duplicate billing. | Proceed only on valid completed audio; otherwise exit 2. No timing-contaminating mid-call retries. |
| Unsupported format/protocol/capability | Fail validation or handshake; name missing capability safely. | No fabricated measurements; exit 2. |
| Recorder overflow/disk failure | Stop the session; report which artifacts were saved and mark incomplete. | Exclude compromised recording; exit 2. If filesystem is unusable, emit safe stderr result. |
| User cancellation | Cancel concurrent tasks, close sockets/clients, flush partial artifacts. | Exit 2 with `cancelled`; no full-call score. |

No post-hoc third-party ASR is silently substituted for the agent's transcript. An optional external transcription study can be added later under different metric names.

## 10. CLI and configuration

Primary command:

```text
voice-eval probe scenario.json --transport ws://localhost:8080/voice --api-key-env ELEVENLABS_API_KEY --protocol-map protocol.json --output-dir out/probe
```

`--caller elevenlabs` is the default. Require a voice ID from `--voice-id` or `ELEVENLABS_VOICE_ID`; an API key alone does not identify a voice. The bundled demo/Kaggle configuration may specify a documented stock voice ID, with an override. Keep model ID explicit in reproducibility config.

Other planned options:

- `--transport-env PROBE_TRANSPORT_URL` to avoid putting signed URLs in process arguments; `--agent-api-key-env PROBE_AGENT_API_KEY` for transport authentication, separate from caller TTS auth.
- `--caller http --caller-url-env CALLER_TTS_URL --caller-model ...` for an external open-model service; optional caller auth env reference.
- `--caller fixture --fixture-manifest ...` for prepared real speech; `--mock` for MockCallerVoice and MockTransport together.
- Existing five metric gate flags plus `--max-barge-in-stop-ms`, timeouts, `--agent-quiet-ms`, and `--seed`.
- `--json` for machine-readable stdout; progress and safe errors to stderr. `--output` names the scored JSON if needed; `--output-dir` contains the whole recording. Keep their meanings distinct.

Config precedence: explicit CLI/API settings, named environment values, documented defaults. Reject contradictory mock/live settings. WS is allowed for local development; WSS uses certificate verification. Bound session length and output volume.

Exit codes remain 0/1/2: 0 means an observed, scorable run passed requested gates and required script behaviors; 1 means measured/behavioral failure or no usable response; 2 means config, transport, provider, recording, or execution error. Operational failures take precedence over quality failures. Artifacts are written before returning whenever possible.

## 13. Top five risks

| Risk | Mitigation and acceptance evidence |
| --- | --- |
| Audio format/rate mismatch | Explicit formats in both directions; request ElevenLabs PCM at the transport rate; validate framing and conformance fixtures; no implicit decoder/resampler. Unsupported formats fail before caller speech. |
| Agent audio appears in caller ASR / echo | Keep channels separate; never route received audio back to the caller stream; require explicit transcript roles. Include a fixture where agent text is mislabeled as caller and reject it. Server-side echo cannot be fixed locally; flag suspicious duplication and investigate rather than subtracting text heuristically. |
| Provider protocol variance | Versioned declarative maps, typed normalized events, explicit capabilities, adapter boundary. Missing correlation/end events degrade the affected measurement honestly. Complex protocols get dedicated future adapters. |
| Timing accuracy and buffering | One monotonic clock, boundary timestamps, paced input, sample offsets, lateness/queue evidence, separate provider clocks, missing-stage indicators, incremental-output requirements for interruption. Document client receipt versus playback and Kaggle location. |
| Live nondeterminism | Frozen scenario, branch selection seed, pinned caller model/settings or exact prerecorded audio, fixed agent config where possible, complete provenance, repeated runs reported separately. Do not claim a TTS seed guarantees identical audio or a one-call diagnostic is a reproducible latency benchmark. |

## 14. Explicitly not building in v0.2

- SIP, PSTN dialing, Twilio/Telnyx adapters or inbound media-stream hosting.
- A dedicated OpenAI Realtime adapter or universal provider auto-detection.
- Browser/WebRTC agent testing, microphone/speaker loopback, acoustic echo cancellation, or physical playback latency measurement.
- In-process model loading, GPU scheduling, model weights in the wheel, model training, or an agent-serving framework.
- A third GPU Kaggle kernel or a public model leaderboard; Kernel A proves harness reproducibility and Kernel B is a diagnostic.
- MP3/Opus/G.711 decoding, general resampling, codecs hidden behind automatic installs.
- An LLM-driven caller, unrestricted branching, semantic outcome judge, or a promise that text confirmation proves a real booking.
- A new CI gate GitHub Action, hosted dashboard, distributed load test, or batch benchmark service. Existing replay CI and CLI gates stay.
- Automatic mid-call reconnect/resume, automatic account provisioning, or automatic publication of user recordings.

Leave these for v0.3 or separate integrations. The v0.2 success criterion is a small, observable, replay-compatible probe that works through a real supported WebSocket and reproduces offline from a published release.
